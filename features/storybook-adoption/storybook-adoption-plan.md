# План внедрения Storybook

Связанный чеклист: [storybook-adoption-implementation-tasks.md](./storybook-adoption-implementation-tasks.md).

## 1. Контекст и проблема

- UI-компоненты проекта развиваются внутри приложения, из-за чего их сложно изолированно просматривать, обсуждать и тестировать.
- Отсутствует единая витрина состояний компонентов (default/disabled/loading/error), что увеличивает риск визуальных регрессий.
- Требуется ввести удобный инструмент для разработки и документирования компонентов без запуска полного пользовательского сценария.

Цель: внедрить Storybook как стандартную среду для изолированной разработки, визуальной проверки и документации UI-компонентов проекта.

## 2. Границы фичи

Входит:

- Инициализация Storybook в текущем React/Vite-проекте.
- Базовая настройка `main`/`preview` конфигурации и общих декораторов (при необходимости).
- Добавление первых историй для ключевых UI-компонентов.
- Настройка npm-скриптов для локального запуска и сборки Storybook.
- Обновление документации проекта по использованию Storybook.

Не входит:

- Полное покрытие историей каждого компонента проекта в рамках одного цикла.
- Полноценная visual regression платформа с внешними SaaS-инструментами.
- Переписывание бизнес-логики компонентов ради Storybook.

## 3. Принципы внедрения

- **Инкрементально:** сначала инфраструктура, затем истории для наиболее важных компонентов.
- **Изоляция без регрессий:** истории не должны изменять поведение компонентов в основном приложении.
- **Переиспользование:** использовать те же UI-компоненты и токены, что и в приложении.
- **Наглядность:** истории покрывают ключевые состояния и edge-case отображения.
- **Поддерживаемость:** структура историй и naming должны быть понятны команде.

## 4. Целевая структура и конфигурация

- В репозитории присутствует рабочая Storybook-конфигурация для React + Vite.
- Добавлены скрипты:
  - локальный запуск Storybook;
  - сборка статической версии Storybook.
- Определена конвенция размещения историй (например, рядом с компонентами или в отдельной директории).
- Для базовых компонентов добавлены истории с несколькими состояниями и controls (где уместно).
- Документация кратко описывает:
  - как запустить Storybook;
  - как добавить новую историю;
  - какие состояния обязательны к покрытию.

## 5. Этапы работ

### Этап A. Подготовка зависимостей и инициализация

- Добавить Storybook-пакеты для React/Vite с exact-версиями.
- После изменения зависимостей выполнить чистую переустановку (`node_modules` и `package-lock.json` удалить, затем `npm install`).
- Инициализировать Storybook и убедиться, что базовый запуск работает.

### Этап B. Базовая конфигурация

- Актуализировать `main` и `preview` конфиги под текущую структуру проекта.
- Настроить загрузку глобальных стилей/темы (если требуется для корректного отображения компонентов).
- Подготовить минимальный набор общих параметров (layout, controls, backgrounds по необходимости).

### Этап C. Первые истории компонентов

- Выбрать приоритетные компоненты UI (кнопки, селекты, статусные блоки и т.п.).
- Добавить истории для ключевых состояний каждого выбранного компонента.
- Проверить, что истории рендерятся корректно и отражают реальное поведение компонентов.

### Этап D. Документация и финальная проверка

- Обновить `README.md` и/или `docs/` инструкциями по запуску и созданию историй.
- Проверить рабочие команды: запуск приложения, `npm run lint`, запуск/сборка Storybook.
- Зафиксировать критерии минимального покрытия историй для новых UI-изменений.

## 6. Риски и меры снижения

- Риск конфликтов конфигурации Storybook и Vite.  
  Мера: начать с официального пресета для React/Vite и минимальных кастомизаций.
- Риск дублирования логики в историях.  
  Мера: использовать реальные компоненты и mock-данные только для представления состояний.
- Риск устаревания историй.  
  Мера: закрепить правило обновлять stories вместе с изменением UI-компонентов.

## 7. Критерии готовности

- Storybook локально запускается и собирается без ошибок.
- Для приоритетных UI-компонентов есть рабочие истории с основными состояниями.
- Документация по использованию Storybook доступна и понятна команде.
- Интеграция не ломает основной workflow разработки приложения.
