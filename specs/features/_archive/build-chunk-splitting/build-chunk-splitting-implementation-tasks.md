# Задачи реализации: разделение сборки на chunks

Связанный план: [build-chunk-splitting-plan.md](./build-chunk-splitting-plan.md).

Используйте чекбоксы по мере выполнения.

---

## Этап A — Анализ и базовая линия

- [x] **A1.** Зафиксировать текущие размеры чанков после `npm run build` (скрин или таблица: entry, крупнейшие `.js` в `dist/assets`).
- [x] **A2.** Построить отчёт о составе бандла (например подключить `rollup-plugin-visualizer` временно или зафиксировать вывод анализа) и отметить, какие модули тянут `@mediapipe/tasks-vision` и страницы.

## Этап B — Lazy-маршруты страниц

- [x] **B1.** Убрать `eager: true` у `import.meta.glob` в `src/routes/routes.ts` или заменить механизм сбора маршрутов на вариант с ленивыми компонентами страниц.
- [x] **B2.** Обеспечить корректный `element` для каждого маршрута через `React.lazy` и `Suspense` (fallback согласовать с UI-темой).
- [x] **B3.** Проверить, что `navItems` и порядок пунктов навигации не сломаны.

## Этап C — Настройка Vite `manualChunks`

- [x] **C1.** Добавить в `vite.config.ts` `build.rollupOptions.output.manualChunks` с осмысленными именами для ключевых vendor-пакетов (как минимум оценить `react`/`react-dom`, `react-router`/`react-router-dom`, `styled-components`).
- [x] **C2.** При необходимости вынести `@mediapipe/tasks-vision` в отдельный chunk через `manualChunks` **или** через dynamic import (этап D) — избежать дублирования одной и той же библиотеки в двух стратегиях без проверки графа.
- [x] **C3.** Прогнать `npm run build` и сравнить с базовой линией из A1.

## Этап D — Отложенная загрузка MediaPipe (по согласованию с планом)

- [x] **D1.** Перевести загрузку `@mediapipe/tasks-vision` на dynamic `import()` в точке инициализации сервиса (или эквивалент), не ломая публичный API `PoseLandmarkerService` для потребителей.
- [x] **D2.** Ручная проверка: старт тренировки/камеры, fallback lite-модели, отсутствие регрессий в консоли.

## Этап E — Документация и финальная проверка

- [x] **E1.** Кратко описать в `README.md` или `docs/`, как смотреть размеры чанков после сборки (если добавлен визуализатор — как его запускать).
- [x] **E2.** `npm run lint`, `npm run test` (если применимо), полная ручная проверка навигации и основного сценария приложения.

---

## Приоритизация (рекомендация)

1. **A1–A2** — база для сравнения.
2. **B1–B3** — максимальный эффект на «первый экран» при росте числа страниц.
3. **C1–C3** — предсказуемое кэширование vendor.
4. **D1–D2** — дополнительное снижение entry, если MediaPipe всё ещё в стартовом графе.
5. **E1–E2** — закрепление и регрессия.

---

## Примечание к B1

Реализован вариант с **ленивыми компонентами страниц** (`React.lazy` + динамический `import` тел страниц в `pages/*/index.tsx`). `import.meta.glob` в `src/routes/routes.ts` по-прежнему с `eager: true`, чтобы синхронно собрать массив `RouteObject` и `navItems`; сами `index.tsx` остаются лёгкими и не импортируют тяжёлые деревья страниц синхронно.
