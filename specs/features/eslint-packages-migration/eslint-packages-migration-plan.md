# План перехода на новый набор ESLint-пакетов

Связанный чеклист: [eslint-packages-migration-implementation-tasks.md](./eslint-packages-migration-implementation-tasks.md).

## 1. Контекст и проблема

- Текущая линтинг-конфигурация не покрывает в полном объеме требования по сортировке импортов, React/React Hooks-правилам и согласованию с Prettier.
- Это приводит к неоднородному стилю кода, шуму в диффах и риску пропуска типовых ошибок в хуках React.
- Требуется перейти на единый и предсказуемый стек ESLint-пакетов с минимальными регрессиями в DX и CI.

Цель: внедрить и стабилизировать набор пакетов:

- `eslint-config-prettier`
- `eslint-plugin-prettier`
- `eslint-plugin-react`
- `eslint-plugin-react-hooks`
- `eslint-plugin-simple-import-sort`

## 2. Границы фичи

Входит:

- Добавление новых ESLint-пакетов в зависимости проекта (с exact-версиями).
- Обновление `eslint.config.js` под flat config и интеграцию новых правил/плагинов.
- Настройка правил сортировки импортов через `simple-import-sort`.
- Настройка совместной работы ESLint и Prettier (`eslint-config-prettier` + `eslint-plugin-prettier`).
- Проверка линтинга в локальном workflow и при необходимости обновление документации.

Не входит:

- Масштабный рефакторинг всего кода ради идеального соответствия новым правилам.
- Изменение бизнес-логики приложения.
- Миграция на альтернативные линтеры/форматтеры вне ESLint/Prettier-стека.

## 3. Принципы внедрения

- **Постепенность:** сначала инфраструктура и конфиг, затем адресные исправления предупреждений/ошибок.
- **Прозрачность:** правила должны быть явными и объяснимыми для команды.
- **Совместимость:** избегать конфликтов между Prettier и ESLint.
- **Минимум шума:** включать только необходимые правила, чтобы не перегрузить команду ложноположительными срабатываниями.
- **Проверяемость:** после настройки обязательно прогонять lint и сборку.

## 4. Целевая конфигурация линтинга

- В `eslint.config.js` подключены:
  - `eslint-plugin-react`
  - `eslint-plugin-react-hooks`
  - `eslint-plugin-simple-import-sort`
  - `eslint-plugin-prettier`
  - `eslint-config-prettier`
- Для React-части включены базовые рекомендованные правила и правила хуков.
- Для импортов включены правила `simple-import-sort/imports` и `simple-import-sort/exports`.
- Конфликтующие форматирующие правила ESLint отключены через `eslint-config-prettier`.
- Ошибки форматирования, при необходимости, выводятся через `prettier/prettier`.

## 5. Этапы работ

### Этап A. Подготовка зависимостей

- Добавить в `package.json` целевые ESLint-пакеты с exact-версиями.
- После изменения зависимостей выполнить чистую переустановку (`node_modules` и `package-lock.json` удалить, затем `npm install`).
- Убедиться, что установка проходит без конфликтов.

### Этап B. Обновление конфигурации ESLint

- Актуализировать `eslint.config.js` под новый стек плагинов и конфигов.
- Настроить правила React и React Hooks.
- Настроить сортировку импортов и экспортов через `simple-import-sort`.
- Интегрировать Prettier в ESLint-конфигурацию без конфликтов.

### Этап C. Адаптация кода под новые правила

- Прогнать `npm run lint` и зафиксировать список ошибок/предупреждений.
- Исправить приоритетные нарушения (hooks/import order/formatting) в затронутых файлах.
- Убедиться, что правки не меняют пользовательское поведение.

### Этап D. Документация и финальная проверка

- При необходимости обновить разделы `README.md`/`docs/` по линтингу и форматированию.
- Проверить итог: `npm run lint`, `npm run build` (и тесты, если релевантны для изменений).
- Зафиксировать готовность к использованию нового линтинг-стека командой.

## 6. Риски и меры снижения

- Риск большого числа линт-ошибок после включения новых правил.  
  Мера: внедрять правила поэтапно и исправлять в первую очередь критичные ошибки.
- Риск конфликтов ESLint и Prettier.  
  Мера: использовать `eslint-config-prettier` и проверять конфиг на дубли/конфликты.
- Риск снижения скорости разработки из-за слишком строгих правил.  
  Мера: стартовать с рекомендованных наборов и точечно усиливать только полезные правила.

## 7. Критерии готовности

- Все 5 целевых ESLint-пакетов подключены и корректно используются в конфиге.
- `npm run lint` проходит стабильно (или оставшиеся предупреждения явно согласованы).
- Сортировка импортов и React Hooks-правила реально применяются.
- Конфликты форматирования ESLint/Prettier устранены.
- Команда имеет понятный ориентир по использованию нового линтинг-стека.
