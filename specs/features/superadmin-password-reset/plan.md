# План фичи: сброс пароля пользователю для superadmin

## Контекст

В админской таблице пользователей у `superadmin` нет штатной операции быстрого сброса пароля. Нужно добавить действие, которое выставляет пользователю временный пароль `12345678` и помечает аккаунт флагом обязательной смены пароля при следующем входе.

## Цель

Добавить безопасный и явный сценарий сброса пароля из интерфейса управления пользователями, доступный только роли `superadmin`.

## Что меняем

- Backend (`server`):
  - новый endpoint для `superadmin`: сброс пароля выбранного пользователя на `12345678`;
  - установка `must_change_password = 1` при таком сбросе;
  - возврат обновлённой записи пользователя в формате admin API.
- Frontend (`src/modules/UserManagementModule`):
  - API-клиент и thunk для вызова reset endpoint;
  - кнопка/действие в таблице пользователей для запуска сброса;
  - обновление строки пользователя и понятные уведомления.

## Ограничения и правила

- Операция доступна только авторизованному `superadmin`.
- Нельзя ломать текущий flow смены роли и существующие ограничения.
- Принудительная смена пароля должна гарантированно устанавливаться после сброса.

## Критерии готовности

- `superadmin` может сбросить пароль пользователя одной операцией из таблицы.
- После сброса пользователь видит `mustChangePassword: true` и должен сменить пароль после входа.
- Не-superadmin получает отказ доступа на API уровне.
- Обновлены/добавлены тесты клиентского слоя и thunk-слоя для новой операции.
