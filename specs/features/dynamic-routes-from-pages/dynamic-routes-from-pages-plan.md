# План: динамическое формирование роутов из описания страниц

Связанный чеклист: [dynamic-routes-from-pages-implementation-tasks.md](./dynamic-routes-from-pages-implementation-tasks.md).

## 1. Контекст и проблема

- Сейчас каждая новая страница требует правок в нескольких местах: константы в `src/routes/paths.ts`, пара `<Route>` в `src/App.tsx`, при необходимости ссылки в `src/components/AppNav/AppNav.tsx`.
- Риск рассинхрона: путь объявлен в одном месте, компонент — в другом, пункт навигации — в третьем.
- **Цель:** маршруты и навигация собираются из **модулей страниц**, подключаемых через **`import.meta.glob`** (Vite), без ручного списка `<Route>` в `App` и без отдельного центрального массива «всех страниц», который нужно править при каждом добавлении.

## 2. Границы фичи

**Входит:**

- Соглашение по **файлу-маркеру** в папке страницы (например, `pageRoute.ts` / `routeModule.ts` — точное имя зафиксировать в реализации), который экспортирует: `path`, компонент страницы (или фабрику элемента), опционально `nav` (подпись, `end` для `NavLink`) и при необходимости стабильный `key` для типобезопасных ссылок.
- В `src/routes/` — **один** модуль-сборщик с `import.meta.glob` по шаблону этих файлов под `src/pages/` (узкий glob, чтобы не подхватить служебные `*.styled.tsx` и прочее).
- На этапе сборки Vite превращает glob в статические импорты; из полученной карты `путь к файлу → модуль` строится упорядоченный список записей маршрута и производные данные для `AppNav` и для `ROUTES` (или эквивалента).
- Сохранение совместимости с баррелями: страницы по-прежнему могут экспортироваться из `pages/index.ts` для прямых импортов вне роутера; модули-маркеры импортируют компонент страницы из своей папки (локальный импорт), а не обязаны тянуть баррель `pages` (снижает риск циклов).
- Сохранение текущего поведения: те же URL (`/`, `/admin`, `/history`), тот же редирект с `*` на главную, главная по-прежнему не тянет лишнюю логику на другие маршруты (граница `WorkoutLogicLayout` остаётся на уровне страницы `HomePage`, а не роутера).

**Не входит (отдельные задачи при необходимости):**

- Lazy-loading страниц: при `import.meta.glob(..., { eager: false })` модули становятся ленивыми; в первом цикле допустим `eager: true` для простоты, либо сразу заложить ленивые импорты и согласовать с типами React Router.
- Защищённые маршруты, вложенные layout-маршруты с общим родителем — только если явно потребуется в реестре (в плане зафиксировать точку расширения).
- Смена библиотеки маршрутизации.

## 3. Модель данных и `import.meta.glob`

### 3.1. Экспорт из модуля-маркера (на страницу)

Минимум:

- `path` — строка URL (как сейчас: `/`, `/admin`, `/history`).
- Компонент страницы или готовый `element` для `<Route>`.

Опционально:

- `key` — стабильный идентификатор для сборки объекта `ROUTES` и типобезопасных ссылок.
- `nav` — `{ label: string; end?: boolean }` для `AppNav`; отсутствие `nav` — страница не в шапке.

### 3.2. Сборщик в `src/routes/`

- Вызов вида `import.meta.glob('../pages/**/<имя-маркера>.ts', { eager: true })` (или `.tsx`, если удобнее держать JSX в маркере — на усмотрение реализации).
- Обход значений карты: для каждого загруженного модуля прочитать экспорты, нормализовать в общий тип «запись маршрута».
- **Порядок:** отсортировать записи так, чтобы более специфичные пути не перекрывались некорректно; маршрут `*` / fallback по-прежнему не из glob, а отдельно в `App` (последним).
- **Производные:** массив для `.map` → `<Route>`; список `nav`; объект `key → path` или прежний `ROUTES`, если ключи сохраняются.

### 3.3. Ограничения и особенности Vite

- API **специфичен для Vite**; при смене сборщика потребуется другой механизм.
- Glob задаётся **строковым литералом** (ограничение Vite для статического анализа).
- Типизация: полная выводимость путей из glob в TypeScript ограничена; для строгих типов ссылок можно оставить явный `as const` объект `ROUTES`, **синхронизированный** с маркерами (проверка в тесте или дублирование `key` в маркерах + рантайм-assert), либо смириться с `string` для `to` в части мест.

### 3.4. Альтернатива (не целевой путь для этой фичи)

Центральный массив записей без glob — проще для типов, но противоречит выбранному подходу «добавил папку страницы + маркер — маршрут подхватился».

## 4. Слои и импорты

- **Маркер** в каждой папке `src/pages/<Name>/` импортирует компонент страницы **из той же папки** (например, `./<Name>.tsx`), не из барреля `pages`, чтобы не создавать цикл «routes → pages barrel → что-то → routes».
- **Сборщик** в `src/routes/` только импортирует результат `import.meta.glob` и экспортирует: список маршрутов, `navItems`, `ROUTES` (если нужен).
- `App.tsx`: `AppNav` + `<Routes>` — итерация по списку из `./routes` + отдельный catch-all.
- `AppNav`: данные навигации только из `./routes` (производные от тех же модулей, что и маршруты).
- Баррель `src/pages/index.ts`: обновлять при добавлении публичной страницы по действующим правилам проекта; маркер не заменяет экспорт страницы для кода, который импортирует страницу напрямую из `pages`.

## 5. Критерии готовности

- Добавление новой обычной страницы сводится к: папка в `pages/`, компонент страницы, **новый модуль-маркер** с `path` (и при необходимости `nav` / `key`), экспорт страницы в `pages/index.ts` по правилам проекта; **не** править список `<Route>` в `App` и **не** добавлять путь вручную в `AppNav`.
- `App.tsx` не содержит ручного списка из трёх и более отдельных `<Route path={…} element={…} />` для известных страниц — только цикл по конфигурации и catch-all.
- Поведение маршрутов и навигации совпадает с текущим: три страницы, редирект неизвестного пути на главную.
- `npm run build`, `npm run lint`, `npm test` проходят.

## 6. Риски

- **Циклические импорты:** маркер → локальный компонент; сборщик → glob. Страницы не должны импортировать сборщик целиком; для ссылок — только `ROUTES` из `./routes`.
- **Типы путей:** динамический glob слабее статического `as const`; при необходимости — дублирование ключей в маркерах + тест на полноту или явный `ROUTES` как «источник для типов».
- **Порядок маршрутов:** явная сортировка записей из glob; catch-all отдельно и последним.
- **Ошибка в маркере:** неверный `path` или дубликат — ловить отладкой или простым рантайм-check при старте (по желанию в рамках фичи).
