# План: декомпозиция крупных файлов в `server/src`

## Контекст

В `server/src` несколько файлов содержат слишком много разнотипной ответственности:

- `index.ts` совмещает HTTP-маршруты, оркестрацию запросов и инфраструктурный bootstrap.
- `db.ts` объединяет типы, SQL-операции и маппинг доменных структур.
- `validation.ts` содержит большой набор схем и проверок в одном месте.

Это усложняет поддержку, точечные изменения и покрытие тестами.

## Цель

- Разделить серверный код на более мелкие и связные модули без изменения внешнего поведения API.
- Снизить размер и связанность ключевых файлов (`index.ts`, `db.ts`, `validation.ts`).
- Подготовить структуру для дальнейших локальных изменений и тестирования.

## Область изменений

- `server/src/index.ts`
- `server/src/db.ts`
- `server/src/validation.ts`
- новые подпапки и баррели внутри `server/src` для роутов, сервисного слоя и валидации
- адаптация импортов в затронутых файлах

## Ограничения и инварианты

- Контракты HTTP-эндпоинтов, коды ответов и формат payload остаются прежними.
- Текущая авторизация и проверка прав не меняются по смыслу.
- SQL-запросы и бизнес-правила не меняются по результату.

## Этапы реализации

1. Выделить модульную структуру (роуты/handlers, валидация, db-операции) и определить границы.
2. Перенести код по слоям с сохранением текущего поведения и обратной совместимости импортов.
3. Упростить `index.ts` до композиции приложения и подключения маршрутов.
4. Прогнать проверки и убедиться в отсутствии регрессии.

## Проверка отсутствия регрессии

- `npm run lint`
- `npm run test` (или эквивалентный набор серверных тестов, если настроен отдельно)
- ручная smoke-проверка ключевых API-эндпоинтов (авторизация, чтение и изменение данных)
