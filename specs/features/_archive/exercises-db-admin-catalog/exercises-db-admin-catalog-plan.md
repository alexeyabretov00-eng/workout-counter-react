# План фичи: справочник упражнений в БД и админ-управление

Ссылка на правила процесса: `README.md`, `specs/features/README.md`.

## Контекст

Сейчас список упражнений на главной странице собирается на фронтенде из `src/modules/HomeModule/exercises/registry.ts`.
Управление списком упражнений из интерфейса отсутствует: `AdminModule` пока рендерит заглушку.

В проекте уже есть API на Express + SQLite (`server/src/index.ts`, `server/src/db.ts`), поэтому справочник упражнений можно вынести в БД без изменения рантайма тренировки.

## Цели

- Хранить в БД только справочник упражнений (метаданные и порядок в списке).
- Получать список упражнений в приложении через API.
- Управлять списком упражнений через админку (CRUD/архивирование).
- Не сохранять в БД состояние выполнения упражнений (повторы, фазы, пауза, отдых, runtime).

## Нецели

- Не переносить алгоритмы детекторов в бэкенд.
- Не внедрять хранение истории тренировок и телеметрии сессии.
- Не менять логику подсчета повторений в `useWorkoutSession`, кроме точки выбора упражнения.

## Технический подход

1. **База данных и серверный слой**
   - Добавить таблицу `exercises` в SQLite и серверные функции доступа (`list`, `create`, `update`, `archive`).
   - Добавить начальные записи для существующих упражнений.

2. **API-контракт**
   - Публичный endpoint для получения списка упражнений.
   - Админ-endpoints для управления упражнениями.
   - Валидация payload и защита от некорректных ссылок на детекторы.

3. **Интеграция с HomeModule**
   - Переключить источник options списка упражнений с локального `exerciseRegistry` на API.
   - Сопоставлять запись из БД с локальным детектором по `detectorKey`.
   - Оставить состояние тренировки в памяти/Redux.

4. **Интерфейс админки**
   - Заменить `AdminPageStub` на экран управления упражнениями.
   - Реализовать список, создание, редактирование и архивирование.
   - Добавить обработку ошибок и обновление списка после операций.

## Этапы

1. Расширить `server/src/db.ts` и схему SQLite таблицей упражнений.
2. Добавить endpoints в `server/src/index.ts` и валидацию входных данных.
3. Добавить клиент API в `src/api` и подключить загрузку упражнений в `HomeModule`.
4. Реализовать CRUD-экран в `src/modules/AdminModule`.
5. Обновить документацию (`README.md`) и прогнать проверки (`lint`, `test`).

## Критерии готовности

- `GET /api/exercises` возвращает актуальный список упражнений из БД.
- Админка позволяет создать, отредактировать и архивировать упражнение.
- Главная страница использует серверный список упражнений.
- При отсутствии/ошибке упражнения в БД приложение не падает и корректно обрабатывает кейс.
- Состояние тренировочной сессии не сохраняется в БД.
- `npm run lint` и `npm run test` проходят успешно.
