# Задачи: динамические роуты из реестра страниц

План: [dynamic-routes-from-pages-plan.md](./dynamic-routes-from-pages-plan.md).

## Чеклист

- [ ] Зафиксировать имя и формат модуля-маркера в папке страницы (экспорты: `path`, компонент/`element`, опционально `key`, `nav`) и шаблон `import.meta.glob` в `src/routes/` (узкий glob, только маркеры).
- [ ] Добавить маркеры для `HomePage`, `AdminPage`, `ExerciseHistoryPage`; в сборщике собрать список маршрутов, порядок (сортировка) и производные `ROUTES` / `navItems` (решить судьбу `paths.ts`: замена или тонкая обёртка над данными сборщика).
- [ ] Переписать `App.tsx`: генерация `<Route>` из списка сборщика + отдельный catch-all `Navigate`.
- [ ] Переписать `AppNav`: пункты из `navItems` (или эквивалент), без хардкода путей.
- [ ] Обновить баррели `src/routes/index.ts` при новых публичных экспортах; убедиться, что маркеры не тянут `pages` barrel (локальные импорты компонента).
- [ ] Проверка: `npm run lint`, `npm run build`, `npm test`; ручной проход трёх маршрутов и редиректа с несуществующего пути.

## Примечания к реализации

- **Имя маркера** выбрать одно на весь проект (например, `pageRoute.ts`), чтобы glob был узким: `import.meta.glob('../pages/**/pageRoute.ts', { eager: true })` — путь относительно файла сборщика в `src/routes/` уточнить при вёрстке каталога.
- **Не включать в glob** `*.styled.tsx`, тесты и прочие файлы — только согласованное имя маркера.
- После мержа плана в `main` ссылки в §7 плана ведут на актуальные issue; при переносе спеки в `_archive` обновить пути в markdown по [docs/markdown-paths.md](../../../docs/markdown-paths.md).
