# План перехода на styled-components

Связанный чеклист: [styled-components-migration-implementation-tasks.md](./styled-components-migration-implementation-tasks.md).

## 1. Контекст и проблема

- Сейчас стили приложения реализованы через существующий подход проекта (глобальные и/или модульные CSS-файлы в UI-слое).
- При росте UI усложняется поддержка согласованных отступов, цветов и состояний компонентов в разных местах.
- Требуется управляемый и поэтапный переход на `styled-components` без регрессий в работе камеры, рендера canvas и UX-сценариев.

Цель: перевести UI-слой на `styled-components` с предсказуемой структурой, едиными стилевыми токенами и безопасной миграцией без «большого взрыва».

## 2. Границы фичи

Входит в фичу:

- Подключение `styled-components` и типизации темы.
- Введение базовой темы (цвета, отступы, радиусы, типографика, состояния).
- Миграция основных React UI-компонентов на styled-подход.
- Удаление устаревших CSS-правил, которые полностью заменены.
- Обновление документации по стилям для команды.

Не входит:

- Редизайн продукта и изменение UX-флоу.
- Переписывание логики детекторов упражнений и сессионного ядра.
- Масштабный рефакторинг бизнес-логики вне UI.

## 3. Принципы миграции

- **Инкрементально:** переносить стили небольшими порциями, сохраняя рабочее состояние после каждого шага.
- **Без изменения поведения:** визуальные правки не должны менять бизнес-логику кнопок, статусов, голосового управления и счётчиков.
- **Единый источник токенов:** цвета/отступы/радиусы централизованы в теме.
- **Минимум глобальных стилей:** оставлять только то, что действительно должно быть глобальным (базовый reset, body, root-контейнер).
- **Тестируемость:** после каждого этапа прогонять линтер, тесты и ручную проверку ключевых пользовательских сценариев.

## 4. Целевая архитектура стилей

- `ThemeProvider` в корневом UI-слое.
- `theme`-объект с токенами:
  - palette (фон, текст, акценты, статусы);
  - spacing (шкала отступов);
  - radius/shadow;
  - typography (размеры/веса, при необходимости).
- Компонентные styled-обертки рядом с React-компонентами или в отдельном `styles`-слое (по выбранной команде конвенции).
- Глобальные стили через `createGlobalStyle` только для базовых правил документа.

## 5. Этапы работ

### Этап A. Подготовка инфраструктуры

- Добавить зависимости `styled-components` и типы для TypeScript.
- Подключить `ThemeProvider` и стартовую тему без изменения визуального поведения.
- Добавить базовый файл глобальных стилей.

### Этап B. Миграция shell/UI-каркаса

- Перенести контейнеры страницы, блоки управления, панели состояния, кнопки и селекты.
- Убедиться, что состояния `disabled/active/hover/focus` соответствуют текущему UI.
- Проверить адаптивность и читаемость на типичных разрешениях.

### Этап C. Миграция оставшихся локальных стилей

- Перенести точечные классы и условные модификаторы в пропсы styled-компонентов.
- Удалить неиспользуемые CSS-правила после миграции конкретных участков.
- Стабилизировать именование и структуру styled-компонентов.

### Этап D. Документация и финализация

- Обновить `README.md`/`docs/architecture.md`: зафиксировать новый подход к стилям.
- Добавить короткие правила для контрибьюторов (как добавлять новые styled-компоненты и токены темы).
- Финально проверить сборку и корректность UI-сценариев.

## 6. Риски и меры снижения

- Риск визуальных регрессий при переносе селекторов.  
  Мера: перенос по блокам + ручной smoke-check после каждого блока.
- Риск дублирования стилей (старые CSS + новые styled).  
  Мера: удалять CSS сразу после подтверждённого переноса конкретного участка.
- Риск разрастания темы без структуры.  
  Мера: договориться о секциях токенов и naming convention заранее.

## 7. Критерии готовности

- Основной UI приложения стилизуется через `styled-components`.
- Тема подключена и используется в ключевых компонентах.
- Устаревшие CSS-файлы/правила удалены или сведены к необходимому минимуму.
- `npm run lint`, `npm run test` и `npm run build` проходят успешно.
- Документация отражает новый подход к стилям.
