# План: динамическая регистрация редьюсеров модулей

## 1. Контекст

Сейчас в `src/store/store.ts` корневой редьюсер собирается статически: `auth`, `admin`, `home` импортируются напрямую и передаются в `combineReducers`.

Нужно оставить `auth` статическим редьюсером, а модульные срезы `admin` и `home` подключать динамически через экспорт из `index.ts` модулей.

## 2. Цель

- Сохранить текущее поведение приложения.
- Убрать жёсткую привязку стора к внутренним файлам `AdminModule` и `HomeModule`.
- Подключать модульные редьюсеры по контракту `reducer = { name, value }`, экспортируемому из `index.ts` модуля.

## 3. Проектирование

- Добавить `src/store/reducerRegistry.ts`:
  - хранение статических редьюсеров;
  - регистрация динамических редьюсеров;
  - загрузка модульных редьюсеров из `src/modules/*/index.ts` через `import.meta.glob(..., { eager: true })`;
  - создание `configureStore` с объединённой картой редьюсеров.
- В `src/store/store.ts`:
  - оставить `auth` в статических редьюсерах;
  - строить `store` и `setupStore` через `ReducerRegistry`.
- В `src/modules/AdminModule/index.ts` и `src/modules/HomeModule/index.ts`:
  - добавить экспорт `reducer` в формате `{ name: '<slice-key>', value: <sliceReducer> }`.

## 4. Проверка

- `ReadLints` для изменённых файлов без новых ошибок.
- Локальная проверка сценариев:
  - авторизация (срез `auth`);
  - открытие админки (`admin`);
  - главный экран тренировки (`home`).

## 5. Вне скоупа

- Асинхронная поздняя подгрузка модулей после старта приложения.
- Миграция других модулей на Redux-срезы.
