# Задачи реализации внедрения commitlint

Связанный план: [commitlint-adoption-plan.md](./commitlint-adoption-plan.md).

Используйте чекбоксы по мере выполнения.

---

## Этап A — Подготовка зависимостей

- [x] **A1.** Добавить `@commitlint/cli` и `@commitlint/config-conventional` в `package.json` с exact-версиями.
- [x] **A2.** После изменения зависимостей выполнить чистую переустановку: удалить `node_modules`, удалить `package-lock.json`, затем выполнить `npm install`.
- [x] **A3.** Проверить, что зависимости установились корректно и не сломали текущие npm-скрипты.

## Этап B — Конфигурация commitlint

- [x] **B1.** Создать конфиг `commitlint` в корне репозитория и подключить conventional-конфиг.
- [x] **B2.** Добавить минимально необходимые локальные правила (только если они действительно нужны проекту).
- [x] **B3.** Проверить `commitlint` вручную на двух сообщениях: одном валидном и одном невалидном.

## Этап C — Интеграция с git hooks

- [x] **C1.** Подключить запуск `commitlint` в hook `commit-msg` через текущий механизм хуков проекта.
- [x] **C2.** Подтвердить, что невалидный commit message блокируется, а валидный проходит.
- [x] **C3.** Проверить, что существующие хуки и сценарии (если есть) продолжают работать без регрессий.

## Этап D — Документация и проверка

- [x] **D1.** Обновить `README.md` и/или `docs/` кратким правилом формата `type(scope): subject`.
- [x] **D2.** Добавить примеры сообщений для `feat`, `fix`, `docs`, `refactor`, `test`, `chore`.
- [x] **D3.** Зафиксировать финальную проверку рабочего процесса коммита (локальный smoke-check).

---

## Приоритизация (рекомендация)

1. **Сначала:** A1-A3, B1 (зависимости и базовая настройка).
2. **Затем:** C1-C3 (включение обязательной проверки в hook).
3. **После:** D1-D3 (документация и закрепление практики).
