# План фичи: динамическая регистрация упражнений

Ссылка на правила процесса: [README.md](../../README.md), [features/README.md](../../features/README.md).

## Контекст

Сейчас реестр упражнений собирается вручную в `src/exercises/registry.ts`: для каждого нового детектора нужно добавить импорт и элемент в массив `exerciseRegistry`.
Это создаёт лишний ручной шаг и риск забыть регистрацию после добавления нового файла детектора.

В бэклоге (`todo.md`) запланирована идея **«Динамическая регистрация»**: подключать детекторы по соглашению, без обязательной ручной правки одного реестра.

## Цели

- Убрать ручное перечисление детекторов в `src/exercises/registry.ts`.
- Автоматически собирать все детекторы упражнений из `src/exercises`.
- Добавить параметр `isActive` в описание упражнения для управления попаданием в список выбора.
- Сохранить обратную совместимость текущего поведения приложения (список упражнений, выбор, работа `getExerciseById`).
- Обновить документацию по добавлению нового упражнения.

## Нецели

- Не менять алгоритмы существующих детекторов.
- Не добавлять новые упражнения в рамках этой фичи.
- Не менять публичные контракты `ExerciseDetector`, кроме добавления `isActive`.

## Технический подход

1. Проверить поддержку `require.context` в текущем стеке (Vite).
2. Если `require.context` недоступен/неподходящий для Vite, использовать эквивалентный механизм динамического импорта через `import.meta.glob` c eager-режимом.
3. Ввести соглашение для файлов детекторов (например, `*Detector.ts`) и/или экспортов.
4. Добавить поле `isActive` в контракт упражнения (с безопасным значением по умолчанию для обратной совместимости).
5. Пересобрать `exerciseRegistry` автоматически на основе найденных модулей и фильтра `isActive`.
6. Добавить защиту от пустого реестра и некорректных модулей.
7. Обновить тесты и документацию.

## Этапы

1. Анализ ограничений сборщика и выбор механизма динамической загрузки.
2. Добавление `isActive` в модель упражнения и текущие детекторы.
3. Рефакторинг `src/exercises/registry.ts` на автоматическое построение реестра с фильтрацией активных упражнений.
4. Адаптация тестов (при необходимости) и документации.
5. Проверка `lint` и `test`.

## Критерии готовности

- Новый детектор, добавленный по соглашению в `src/exercises`, появляется в реестре без ручной правки списка импортов.
- Упражнение с `isActive: false` не появляется в UI-списке и не участвует в голосовом выборе упражнения.
- `npm run lint` и `npm run test` проходят успешно.
- README (раздел «Как добавить новое упражнение») отражает новый процесс регистрации.
