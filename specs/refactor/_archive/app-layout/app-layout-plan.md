# План: ввести `AppLayout`

## 1. Контекст

В `src/App.tsx` корневая разметка — это `<main className="app">` с четырьмя последовательными `<section>` (заголовок, панель управления, статус-бар, сцена). Раскладка страницы (сетка, отступы, ограничение ширины) задана в `src/App.css` классом `.app`. Логика хуков и содержимое секций смешаны в одном компоненте; выделение **оболочки страницы** упростит дальнейшее вынесение секций и сохранит единое место для скелета UI.

## 2. Цель

- Добавить презентационный компонент **`AppLayout`**, который отвечает только за структуру страницы: корневой `<main>`, четыре именованные области.
- Проброс содержимого областей через **явные слоты** (пропсы типа `ReactNode`): `header`, `controls`, `statusBar`, `stage` — без дублирования хуков в дочерних «контейнерах`; состояние сессии и голоса остаётся в текущем родителе (`App` или, при последующем шаге, отдельной странице).
- Перенести стили, относящиеся **к корневой раскладке** (эквивалент текущего `.app`), в `src/components/AppLayout/AppLayout.css` и подключать их из `AppLayout.tsx`.
- Наблюдаемое поведение и внешний вид приложения **не меняются**.

## 3. Предлагаемая структура файлов

| Путь | Назначение |
|------|------------|
| `src/components/AppLayout/AppLayout.tsx` | Компонент `AppLayout`: рендер `<main>` и четырёх `<section>` с переданными слотами |
| `src/components/AppLayout/AppLayout.css` | Стили корня layout (сетка, gap, max-width, padding); при необходимости классы секций уровня layout (например обёртки с BEM: `app-layout`, `app-layout__header`, …) |
| `src/components/AppLayout/index.ts` | Явный реэкспорт `AppLayout` (без `export *`) |
| `src/components/index.ts` | Реэкспорт `AppLayout` для импорта из `App.tsx` как `from './components'` |

## 4. Контракт `AppLayout`

- Четыре пропса: `header`, `controls`, `statusBar`, `stage` — тип `ReactNode` (или `React.ReactNode`).
- Семантика секций сохраняется: как сейчас — заголовок, блок управления, строка статусов, область сцены; классы вида `header`, `controls`, `status-bar`, `stage` можно оставить на `<section>` для совместимости с существующими правилами в `App.css` **или** перенести только то, что станет частью `AppLayout.css` (см. раздел «Стили»).
- Компонент **не** использует `useWorkoutSession`, `useSpeechRecognition` и другие хуки сессии.

## 5. Стили

- Вынести из `App.css` в `AppLayout.css` правила, относящиеся к **корневому контейнеру страницы** (сейчас `.app`: margin, max-width, padding, display grid, gap).
- Секционные классы (`.header`, `.controls`, `.status-bar`, `.stage` и всё, что относится к статусам, сцене, лоадеру и т.д.) на первом этапе можно **оставить в `App.css`**, чтобы минимизировать объём правок и риск визуальной регрессии; либо перенести в `AppLayout.css` только классы обёрток секций, если они переименованы под префикс `app-layout__*`, и обновить разметку соответственно.
- Глобальное правило `* { box-sizing: border-box; }` в `App.css` не обязано переезжать в `AppLayout` — оставить в `App.css` или в корневом стиле приложения по текущей договорённости проекта.

После изменений внешний вид страницы должен совпадать с текущим.

## 6. Изменения в `App.tsx`

- Импортировать `AppLayout` из `./components`.
- Обернуть текущий `return` так, чтобы тело секций передавалось в `AppLayout` четырьмя слотами; логика хуков, состояние и обработчики **без изменений**.

## 7. Этапы реализации

1. Создать папку `AppLayout`, реализовать `AppLayout.tsx` с четырьмя слотами и разметкой, близкой к текущей.
2. Добавить `AppLayout.css`, перенести стили корня `.app` (и при необходимости переименовать корневой класс на BEM для `AppLayout`, обновив разметку).
3. Обновить `src/components/index.ts`.
4. Подключить `AppLayout` в `App.tsx`, удалить дублирующую обёртку `<main className="app">` и вложенные `<section>` с уровня `App` в пользу пропсов `AppLayout`.
5. Подчистить `App.css` от перенесённых правил.

## 8. Проверка отсутствия регрессии

- Ручная проверка: сетка страницы, отступы, ширина; старт/пауза/сброс/стоп; селекты; статусы; сцена и камера.
- `npm test` и `npm run build` проходят без ошибок.

## 9. Критерии готовности

- `AppLayout` живёт в `src/components/AppLayout/` с `index.ts` и явным реэкспортом в барреле `src/components/index.ts`.
- `App.tsx` использует `AppLayout` со слотами; хуки остаются в `App` (или в одном родителе выше презентации).
- Раскладка корня страницы описана рядом с `AppLayout`, а не размазана только по `App.tsx`.
- Поведение и визуал совпадают с состоянием до рефакторинга.

## 10. Вне скоупа (последующие задачи)

- Вынесение секций в отдельные компоненты (`WorkoutControls`, `SessionStatusBar` и т.д.) и выделение `WorkoutPage` — отдельные рефакторинги после стабилизации `AppLayout`.
