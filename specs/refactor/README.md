# Планы рефакторинга

- **Активные** задачи — подкаталоги здесь же: `specs/refactor/<краткое-имя>/` (не используйте `_archive` для новой работы).
- **Рефакторинг** — перестройка кода **без** изменения наблюдаемого поведения продукта для пользователя. Новая функциональность — в `specs/features/`, исправления и хотфиксы — в `specs/fixes/` (см. их README).
- После **реализации** (чеклист закрыт, регрессии нет) **перенесите** каталог в `specs/refactor/_archive/<то же имя>/` **отдельным третьим коммитом** цикла (см. раздел «Планирование фич и исправлений» в корневом `README.md`). Ссылки на файлы в markdown — по `docs/markdown-paths.md` (путь от корня в `` `...` ``, без `../`).
- **Архив** только для истории; продолжение темы — новый каталог `specs/refactor/<имя>/` с планом и чеклистом.

Полные критерии «что считать рефакторингом» и исключения: [.cursor/rules/feature-planning.mdc](../../.cursor/rules/feature-planning.mdc).
