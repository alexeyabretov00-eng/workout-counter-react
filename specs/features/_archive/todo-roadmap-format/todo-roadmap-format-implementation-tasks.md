# Задачи: преобразование todo в читаемый формат

> **Архив:** материалы в `specs/features/_archive/todo-roadmap-format/`. См. `specs/features/README.md`.

Связанный план: [todo-roadmap-format-plan.md](./todo-roadmap-format-plan.md).

Используйте чекбоксы по мере выполнения.

---

## Этап A — Инвентаризация

- [x] **A1.** Выписать из `todo.md` все пункты в виде таблицы «исходная строка → предлагаемый раздел → краткий смысл» (черновик можно держать в комментарии к PR или внизу плана до слияния).
- [x] **A2.** Отметить логические зависимости между пунктами (текстом под списком или в колонке «заметки»), без обязательной фиксации приоритетов в коде.

## Этап B — Структура

- [x] **B1.** Утвердить финальный набор заголовков `##` и их порядок в будущем `todo.md`.
- [x] **B2.** Решить: нужна ли в начале файла таблица-обзор; если да — определить колонки (например: направление, кратко, примечание).

## Этап C — Перенос в todo.md

- [x] **C1.** Переписать `todo.md`: вводный блок, разделы, вложенные списки; пункт про таймер отдыха по завершении упражнения оформить как подзадачу блока про голос/сессию (или выбранный раздел), без номера `0.1`.
- [x] **C2.** Пройтись по чеклисту из A1: каждая исходная идея имеет явное место в новом тексте.
- [x] **C3.** Проверить превью markdown (GitHub или локально): заголовки, отступы списков, таблица (если есть).

## Этап D — Точки входа и консистентность

- [x] **D1.** Сверить `README.md`: ссылка на `todo.md` и формулировка «бэклог идей» остаются корректными; при смене смысла документа — минимально поправить одну фразу.
- [x] **D2.** Поиск по репозиторию на `todo.md` и «дорожн» / «бэклог»: при необходимости обновить устаревшие описания формата списка (например, в `specs/features/_archive/documentation/documentation-update-plan.md`, если там всё ещё говорится о «плоском» виде как о проблеме после правок).
