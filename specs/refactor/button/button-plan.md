# План: вынести кнопки из `src/App.tsx`

## 1. Контекст

В `src/App.tsx` в секции `.controls` три нативных `<button type="button">` с общим внешним видом: старт/пауза, сброс, стоп. Разметка и поведение заданы inline; стили лежат в `App.css` под селектором `.controls button` (базовый вид, `:hover`, `:disabled`).

## 2. Цель

- Вынести **один** переиспользуемый компонент **`Button`** для всех трёх случаев.
- Разместить его в **отдельной папке** `src/components/Button/` с публичным API через `index.ts` (явные реэкспорты, без `export *`).
- Держать **стили рядом с компонентом**: `src/components/Button/Button.css`, импортируемый из `Button.tsx`.
- Расширить баррель `src/components/index.ts`, чтобы из `App.tsx` импорт был вида `import { Select, Button } from './components'` (или две строки импорта из одного барреля — по текущему соглашению проекта).

Поведение и доступность для пользователя не меняются: те же подписи, `aria-label` где они есть, условия `disabled`, обработчики `onClick`.

## 3. Предлагаемая структура

| Путь | Назначение |
|------|------------|
| `src/components/Button/Button.tsx` | Компонент `Button`: обёртка над `<button type="button">` с классом(ами) из `Button.css` |
| `src/components/Button/Button.css` | Стили кнопки (перенос из правил `.controls button` в `App.css`) |
| `src/components/Button/index.ts` | Явный реэкспорт `Button` и типов пропсов при необходимости |
| `src/components/index.ts` | Добавить явный реэкспорт `Button` (и типов) |

## 4. Контракт компонента (на уровне идеи)

Минимально достаточные пропсы:

- `children: ReactNode` — текст или содержимое кнопки.
- `onClick: () => void` (или `MouseEventHandler`, если удобнее для типизации) — вызов из `App` без смены логики.
- `disabled?: boolean`.
- `aria-label?: string` — для кнопок «Старт/Пауза» и «Стоп», где подпись задаётся через `aria-label`.
- `type` зафиксировать как `"button"` внутри компонента, чтобы не дублировать и не получить случайный submit.

Опционально позже: `className` для расширения без изменения базового вида.

Логику `useWorkoutSession`, условия `disabled` и разветвление старт/пауза оставить в `App.tsx`; `Button` остаётся презентационным.

## 5. Стили

- Перенести в `Button.css` правила, сейчас привязанные к `.controls button`, `.controls button:hover`, `.controls button:disabled` в `src/App.css`.
- На элемент `<button>` вешать явный класс (например BEM: `button__root` или `app-button`), чтобы стили не зависели от родителя `.controls`.
- В `App.css` у `.controls` оставить только **раскладку** (flex, gap, выравнивание); блоки стилей кнопок из `App.css` удалить после переноса.

Внешний вид кнопок в панели управления после переноса должен совпадать с текущим.

## 6. Этапы реализации

1. Добавить `Button/`, `Button.css`, импорт стилей в `Button.tsx`, обновить `src/components/index.ts`.
2. Заменить в `App.tsx` три `<button>` на `<Button />` с соответствующими пропсами.
3. Синхронизировать `App.css` и `Button.css` по разделу «Стили» выше.

## 7. Проверка отсутствия регрессии

- Ручная проверка: старт, пауза, сброс, стоп; состояния `disabled` до старта, во время отдыха и т.д. как сейчас.
- `npm test` и `npm run build` проходят без ошибок.

## 8. Критерии готовности

- В `App.tsx` нет трёх отдельных нативных кнопок в панели управления — используется один импортируемый `Button`.
- Стили кнопки живут в `src/components/Button/Button.css`.
- Импорты между папками `src` соблюдают правило баррелей с явными экспортами.
- Наблюдаемое поведение UI совпадает с состоянием до рефакторинга.
