# Пути к файлам в markdown

## Зачем не использовать `../` в ссылках

Относительные ссылки вида `[файл](../../../README.md)` зависят от глубины каталога: при переносе плана в архив нужно вручную добавлять ещё один `../`. Это ломается и отвлекает от смысла.

## Соглашение для этого репозитория

1. **Путь от корня репозитория в обратных кавычках** — основной способ указать файл или каталог:
   - `src/hooks/useWorkoutSession.ts`
   - `README.md`
   - `specs/README.md`
   - `specs/features/README.md`
   - `specs/fixes/README.md`
   - `specs/refactor/README.md`
   - `docs/architecture.md`

2. **Кликабельная ссылка на GitHub** (если нужен переход по клику в веб-интерфейсе): полный URL вида  
   `https://github.com/<org>/<repo>/blob/main/src/hooks/useWorkoutSession.ts`  
   (ветку `main` замените при необходимости.)

3. **Ссылки между соседними документами** в одном каталоге по-прежнему можно делать коротко: `./implementation-tasks.md`.

4. Относительные пути с `../` **не запрещены** в старых архивных материалах, но **новые** планы и правки лучше оформлять по пунктам 1–2.

5. Для массовой замены старых ссылок в `specs/features/`, `specs/fixes/` и `specs/refactor/` можно запустить из корня репозитория: `node scripts/normalize-md-paths.mjs` (после правок просмотрите diff: если подпись ссылки и целевой файл различались, строку может понадобиться поправить вручную).
