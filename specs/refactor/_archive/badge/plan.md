# План: универсальный компонент `Badge`

## 1. Контекст

В `src/components/WorkoutStatusBar/WorkoutStatusBar.styled.tsx` общий фрагмент `pillBase` (отступы, скругление «пилюли», бордер, нейтральный фон) повторяется для четырёх styled-элементов: бейджи модели, камеры, голоса и примечание о паузе сессии. Цвета и фоны задаются через `theme.palette.status.*` и `theme.palette.text.gray600` / `gray700` в зависимости от строковых статусов или флага готовности камеры.

Строки статусов (`modelStatus`, `voiceStatus`) и смысл «камера готова / нет» относятся к домену экрана тренировки; визуальные варианты — к дизайн-слою.

## 2. Цель

- Вынести **один** переиспользуемый презентационный компонент **`Badge`** с вариантами оформления, сопоставимыми с токенами темы (успех, информация, ошибка, предупреждение, нейтральное состояние, приглушённый текст, заметка).
- Разместить виджет в `src/components/Badge/` по соглашению проекта: `Badge.tsx`, `Badge.styled.tsx`, `index.ts` с явными реэкспортами; стили — **styled-components** и значения из `src/theme`.
- Подключить `Badge` в `WorkoutStatusBar`: **маппинг** «доменный статус / флаг → `variant`» остаётся в `WorkoutStatusBar.tsx` (или в небольших чистых функциях рядом в папке статус-бара), без переноса строк вроде `listening` или `inactive-tab` внутрь `Badge`.
- Сохранить **наблюдаемое поведение и внешний вид** статус-бара для пользователя (те же комбинации цветов и тексты).

`WorkoutStatusBarCameraError` — не пилюля, только цвет ошибки; в плане не обязательно включать в `Badge`, можно оставить локальным styled-элементом в `WorkoutStatusBar.styled.tsx` или заменить на семантически подходящий вариант только если это не меняет разметку/классы критично для тестов (по умолчанию — без изменения вида).

## 3. Предлагаемая структура

| Путь | Назначение |
|------|------------|
| `src/components/Badge/Badge.tsx` | Компонент `Badge`: `children`, проп `variant`, рендер в styled-обёртку (например `<span>`). |
| `src/components/Badge/Badge.styled.tsx` | Общий базовый стиль пилюли + ветвление по `$variant` и `theme.palette`. Имя корневого styled-узла по соглашению с префиксом виджета, например `BadgeRoot`. |
| `src/components/Badge/index.ts` | Явный реэкспорт `Badge`, типа `BadgeProps` / `BadgeVariant` при необходимости. |

| `src/components/WorkoutStatusBar/WorkoutStatusBar.tsx` | Использование `Badge` с вычислением `variant` из текущих пропсов. |
| `src/components/WorkoutStatusBar/WorkoutStatusBar.styled.tsx` | Оставить `WorkoutStatusBarRoot`, `WorkoutStatusBarCameraError` (и при необходимости другие не-бейдж элементы); убрать дублирующие пилюли. |

## 4. Контракт `Badge` (на уровне идеи)

- `children: ReactNode` — подпись бейджа.
- `variant` — дискриминант визуала; набор значений согласовать с фактическими сочетаниями в текущем `WorkoutStatusBar`, например:
  - цветные статусы из темы: успех, информация, ошибка, предупреждение (аналог текущих веток `success` / `info` / `error` / `warning` в `theme.palette.status`);
  - **нейтральный** вариант: только база пилюли (как сейчас `default` у модели/голоса с пустым дополнительным CSS);
  - **приглушённый**: база + цвет текста `gray600` (камера «off», голос `unsupported`);
  - **заметка**: база + `gray700` (текст «Упражнение приостановлено»).
- Transient prop для styled: `$variant` (не попадать в DOM).
- Логику сессии, строки статусов с бэка/хуков не импортировать в `Badge`.

## 5. Соответствие текущему UI (для маппинга в `WorkoutStatusBar`)

Зафиксировать в реализации таблицу соответствий 1:1 с нынешними ветками:

- **Модель:** `ready` → успех; `loading` → информация; `error` → ошибка; иначе → нейтраль.
- **Камера:** готова → успех; иначе → приглушённый.
- **Голос:** `listening` → информация; `inactive-tab` → предупреждение; `blocked` / `error` → ошибка; `unsupported` → приглушённый; иначе → нейтраль.
- **Пауза:** один бейдж с вариантом «заметка».

## 6. Этапы реализации

1. Добавить `Badge/` (tsx, styled, `index.ts`) и реэкспорт в барреле `src/components/index.ts`.
2. В `WorkoutStatusBar` заменить четыре пилюли на `Badge` с вычислением `variant`; удалить неиспользуемые styled-компоненты из `WorkoutStatusBar.styled.tsx`.
3. Прогнать `npm test` и `npm run build`; визуально проверить статус-бар во всех типичных состояниях (модель, камера, голос, пауза, ошибка камеры).

## 7. Проверка отсутствия регрессии

- Ручная проверка: те же цвета и читаемость бейджей, что до рефакторинга.
- Автоматические проверки: тесты и сборка без ошибок.

## 8. Критерии готовности

- Публичный `Badge` доступен из `src/components/index.ts`.
- В `WorkoutStatusBar` нет четырёх отдельных styled-пилюль с дублированием `pillBase`; общая стилизация сосредоточена в `Badge.styled.tsx`.
- Доменные статусы не захардкожены внутри `Badge`.
- Внешний вид и тексты статус-бара для пользователя совпадают с состоянием до рефакторинга.
