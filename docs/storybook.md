# Storybook

Изолированная витрина UI-компонентов: [Storybook](https://storybook.js.org/) с пресетом **React + Vite** (те же алиасы путей, что и в приложении).

## Команды

- **`npm run storybook`** — dev-сервер (по умолчанию порт **6006**).
- **`npm run build-storybook`** — статическая сборка в каталог **`storybook-static/`** (каталог в `.gitignore`).

## Где лежат истории

Истории лежат в подпапке **`__stories__`** рядом с компонентом:

- общие UI: `src/components/<Name>/__stories__/<ComponentName>.stories.tsx`;
- виджеты страниц: `src/pages/<PageName>/components/<Name>/__stories__/<ComponentName>.stories.tsx`.

Импорты самого компонента в истории — из **локального барреля папки виджета**: **`import { … } from '..'`** (тот же `index.ts`, что и для тестов рядом; из `__tests__/` это выглядело бы как `from '../ComponentName'`). Алиасы вроде **`@components`** в stories не обязательны. Тема для превью задаётся в **`.storybook/preview.tsx`** (`@theme`), отдельно в файлах историй подключать её не нужно.

## Минимальные правила для новых UI

- Для нового или существенно изменённого компонента добавляйте или обновляйте историю в том же цикле, что и правки компонента.
- Покрывайте заметные состояния: по смыслу компонента (например **`default`**, **`disabled`**, варианты стилей/типов).
- По возможности включайте **`autodocs`** (`tags: ['autodocs']` в `meta`), чтобы в панели Docs была сводка пропсов.

## Линтинг

Для файлов историй действует **`eslint-plugin-storybook`** (см. `eslint.config.js`).
