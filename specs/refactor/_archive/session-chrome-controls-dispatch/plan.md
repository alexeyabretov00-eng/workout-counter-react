# План: единый API действий для chrome-контролов сессии (`dispatch` вместо четырёх колбеков)

## 1. Контекст

Срез **`WorkoutSessionChromeControls`** сейчас публикует четыре отдельные функции — `start`, `pause`, `reset`, `shutdown` — в типе `WorkoutSessionChromeControlsValue` (`src/contexts/WorkoutSessionChromeControls/types.ts`). Их потребляют:

- **`ExerciseControlBarContainer`** через **`useExerciseControlBarContainerSelector`** — деструктуризация четырёх имён в разметке кнопок;
- **`useSpeechRecognition`** — параметры хука и внутренние `ref` на те же четыре функции для голосовых команд (`src/hooks/useSpeechRecognition.ts`).

Реализация сессии по-прежнему в **`useWorkoutSession`**; меняется только **форма публичного контракта** chrome-контекста и точки вызова у UI/голоса.

## 2. Цель

- Заменить четыре поля-колбека в значении chrome-контекста на **один вызов** в стиле действий: например **`dispatchWorkoutSessionChromeControl(action)`** (имя согласовать при реализации; далее в плане — условно **`dispatch`**).
- Сохранить **наблюдаемое поведение** приложения (кнопки, голос, асинхронный `start`, `shutdown` с опциональным override длительности отдыха).
- Сохранить **стабильность ссылки** на **`dispatch`** там, где это важно для подписчиков контекста (по аналогии с текущими `useCallback` из `useWorkoutSession`): собирать **`dispatch`** в **`WorkoutLogicLayout`** через **`useCallback`** с корректными зависимостями.

## 3. Проектирование API

### 3.1. Тип действия

Ввести дискриминирующий union, согласованный с существующими операциями, например:

- `{ type: 'start' }` — соответствует текущему `start()` (в т.ч. `void` при вызове из обработчиков);
- `{ type: 'pause' }`;
- `{ type: 'reset' }`;
- `{ type: 'shutdown'; restDurationOverrideMs?: number }` — опциональный аргумент как у текущего `shutdown`.

Тип и функция **`dispatch`** экспортировать из слоя контекстов (тип — рядом с `WorkoutSessionChromeControlsValue`, например в `src/contexts/WorkoutSessionChromeControls/types.ts` или отдельный файл типов в той же папке с явным реэкспортом в **`index.ts`** папки контекста).

### 3.2. Провайдер

В **`WorkoutLogicLayout`** реализовать **`dispatch`** телом **`switch (action.type)`**, вызывающим существующие **`start`**, **`pause`**, **`reset`**, **`shutdown`** из **`useWorkoutSession`**. Побочные эффекты и **`async`** остаются в этих функциях; **`dispatch`** сам может быть синхронным, а для **`start`** внутри ветки вызывать **`void start()`** при необходимости.

Объект **`controlsValue`** для провайдера: убрать четыре поля, добавить одно поле **`dispatch`** (или выбранное финальное имя). Обновить **`useMemo`**-зависимости так, чтобы они отражали стабильность **`dispatch`**.

### 3.3. Потребители

1. **`useExerciseControlBarContainerSelector`** — возвращать **`dispatch`** (и не возвращать четыре старых поля). Зависимости **`useMemo`** селектора сузить соответственно.
2. **`ExerciseControlBarContainer`** — вызывать **`dispatch({ type: '…' })`** в обработчиках вместо отдельных функций.
3. **`useSpeechRecognition`** — на выбор (зафиксировать в реализации один вариант):
   - **Вариант A (минимальный дифф в хуке):** параметры хука заменить на **`dispatch`** и тип действия; внутри хука **`ref`** на **`dispatch`** и вызовы **`dispatchRef.current({ type: 'pause' })`** и т.д. вместо четырёх ref;
   - **Вариант B:** оставить хук с четырьмя колбеками, но в **`WorkoutLogicLayout`** передавать четыре **`useCallback`**, которые внутри только делегируют в **`dispatch`** — тогда сигнатура **`useSpeechRecognition`** не меняется, но дублирование тонких обёрток остаётся.

Рекомендация плана: **вариант A**, чтобы единая форма «команды сессии» жила и в UI, и в голосе.

### 3.4. Баррели и импорты

- Обновить **`src/contexts/WorkoutSessionChromeControls/index.ts`** и при необходимости **`src/contexts/index.ts`** — явные реэкспорты типа действия и при необходимости вспомогательных типов (**без** `export *`).
- Проверить **`src/logic/index.ts`**, если типы chrome-контролов реэкспортируются наружу для контейнеров.

## 4. Критерии готовности

- Нет обращений к **`start` / `pause` / `reset` / `shutdown`** как к полям **`WorkoutSessionChromeControlsValue`** вне **`WorkoutLogicLayout`** (только **`dispatch`**).
- **`npm run lint`**, **`npm test`**, **`npm run build`** проходят.
- Ручная проверка: старт/пауза с кнопки и голосом; сброс и стоп; сценарий с отдыхом и override длительности (если есть в голосовых командах) — без регрессии.

## 5. Вне скоупа

- Внутренняя машина состояний **`useWorkoutSession`** (в т.ч. уже введённый **`useReducer`** для статуса сессии) — не обязательная часть этой задачи.
- Изменение набора команд (новые типы действий) — отдельная фича, если понадобится после рефакторинга.
