# План внедрения React Router

Связанный чеклист: [react-router-routing-implementation-tasks.md](./react-router-routing-implementation-tasks.md).

## 1. Контекст и цель

- Сейчас приложение — один экран: в `src/App.tsx` дерево `WorkoutLogicLayout` → `AppLayout` с контейнерами тренировки.
- Нужна навигация по трём маршрутам без изменения поведения счётчика на главной странице.
- **Цель:** подключить `react-router` и `react-router-dom` (оба в `dependencies` с точными версиями), вынести маршруты, добавить две заглушки («Админка», «История упражнений»), сохранить текущий UI главной страницы.

## 2. Маршруты и URL

| Путь | Назначение |
|------|------------|
| `/` | Главная — текущее содержимое бывшего `App.tsx` (логика тренировки + layout). |
| `/admin` | Страница-заглушка «Админка». |
| `/history` | Страница-заглушка «История упражнений». |

Имена путей можно зафиксировать как константы (например, в модуле маршрутов), чтобы не дублировать строки в ссылках и в `Route`.

**Корень приложения:** по умолчанию `BrowserRouter` с `basename` не задаётся (корень сайта). Если позже понадобится деплой не с `/`, это отдельная настройка в `vite` и `BrowserRouter`.

## 3. Границы фичи

**Входит:**

- Зависимости **`react-router`** и **`react-router-dom`** с **точными** версиями в `package.json` (версии взять из одного релиза React Router, чтобы ядро и DOM-слой совпадали), затем чистая переустановка по правилам репозитория.
- Обёртка приложения роутером (типично в `src/main.tsx` или в корневом компоненте сразу под `ThemeProvider`).
- Три маршрута; главная визуально и по поведению совпадает с текущим приложением.
- Минимальная навигация между страницами (например, шапка или компактный блок ссылок), чтобы маршруты были проверяемы вручную без ручного ввода URL.

**Не входит:**

- Реализация функционала админки и истории (только заглушки).
- Сохранение/восстановление состояния тренировки при уходе с главной и возврате (если не требуется явно — оставляем как есть).
- Защита маршрутов, роли, lazy-load страниц (по желанию — последующие фичи).

## 4. Архитектура и слои

### 4.1. Где живёт логика тренировки

`WorkoutLogicLayout` подключает провайдеры и эффекты сессии/камеры. Его нужно рендерить **только для маршрута `/`**, иначе заглушки потянут ненужную инициализацию и побочные эффекты.

Рекомендуемая схема:

- Компонент страницы «Главная» (например, `HomePage`) внутри себя рендерит `WorkoutLogicLayout` и прежнее дерево с `AppLayout`.
- Страницы `/admin` и `/history` — простой контент без `WorkoutLogicLayout`.

### 4.2. Размещение страниц

Согласованно с баррелями и `imports-via-index`:

- Ввести каталог `src/pages/` (или эквивалентное имя, принятое в команде) с подпапками на страницу: `HomePage/`, `AdminPage/`, `ExerciseHistoryPage/` — в каждой `*.tsx`, при необходимости `*.styled.tsx`, `index.ts` с явными реэкспортами.
- Баррель `src/pages/index.ts` реэкспортирует публичные страницы; импорты из других верхнеуровневых папок `src` — из барреля `pages`.

Альтернатива меньшего объёма: один файл `src/routes.tsx` с тремя маленькими компонентами маршрутов — допустима, если команда не вводит `pages/`; в чеклисте зафиксирован вариант с `src/pages/` как более масштабируемый.

### 4.3. Корень маршрутизации

- `Routes` / `Route` и опционально `Navigate` для редиректа с неизвестного пути на `/` или простая страница 404 — на усмотрение реализации (минимум: три объявленных маршрута).
- Корневой компонент приложения (`App.tsx` или выделенный `AppRoutes`) содержит только разметку роутера и вложенные `Route`, без дублирования бизнес-логики.

## 5. Этапы работ

1. **Зависимости:** добавить `react-router` и `react-router-dom` (exact, согласованные версии), чистая переустановка `node_modules` и lockfile.
2. **Страницы:** реализовать три страницы; главная — перенос текущего JSX из `App.tsx`.
3. **Роутер:** подключить `BrowserRouter`, объявить маршруты, заменить в `main.tsx` прямой рендер «старого» `App` на приложение с роутингом.
4. **Навигация:** `Link` или общий layout с ссылками на `/`, `/admin`, `/history`.
5. **Проверка:** `npm run build`, `npm run lint`, `npm test` (если есть релевантные тесты), ручной проход трёх URL и переходов по ссылкам.

## 6. Критерии готовности

- Три маршрута открываются и отображают ожидаемый контент.
- Главная страница не регрессирует (старт/пауза, контейнеры, статус — как до внедрения).
- Админка и история не оборачиваются в `WorkoutLogicLayout`.
- Импорты между папками `src` идут через баррели, без `export *` в `index.ts`.

## 7. Риски

- **Лишняя инициализация на всех маршрутах** — снимается изоляцией `WorkoutLogicLayout` на `/` только.
- **Жёстко прошитые пути** — снимаются константами маршрутов.
- **SPA на проде** — для статического хостинга все пути должны отдавать `index.html` (отдельная задача деплоя, при необходимости документировать в `README`).
