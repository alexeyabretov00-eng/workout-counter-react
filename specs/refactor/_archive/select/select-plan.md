# План: вынести разметку select из `App.tsx`

## 1. Контекст

В `src/App.tsx` в секции «controls» два фрагмента с одинаковой структурой: `<label>` + нативный `<select>` с перечислением `<option>`. Это дублирует разметку и усложняет чтение корневого компонента приложения.

## 2. Цель

- Вынести **один** переиспользуемый компонент **`Select`**, который инкапсулирует связку «подпись + select».
- Разместить его **в отдельной папке** `src/components/Select/` с явным публичным API через `index.ts` (см. правило импортов через баррель).
- Держать **стили компонента рядом с ним**: отдельный файл CSS в `src/components/Select/`, подключаемый из `Select.tsx` (не оставлять оформление самого поля только в `App.css`).

Поведение для пользователя не меняется: те же `id`, подписи, значения, `disabled` у выбора упражнения во время сессии, опции из `exerciseRegistry` и `REST_DURATION_OPTIONS`.

## 3. Предлагаемая структура

| Путь | Назначение |
|------|------------|
| `src/components/Select/Select.tsx` | Реализация компонента `Select` (внутри — нативный `<select>`) |
| `src/components/Select/Select.css` | Стили только для `Select` (подпись, поле, состояние `disabled`, оформление chevron и т.д.) |
| `src/components/Select/index.ts` | Явный реэкспорт компонента (без `export *`) |
| `src/components/index.ts` | Баррель каталога `components` для импорта из `App.tsx` как `from './components'` |

## 4. Контракт компонента (на уровне идеи)

Один компонент `Select`, параметризуемый данными:

- Подпись и связь с полем: `label`, `id` (как сейчас `htmlFor` у label и `id` у select).
- Состояние: `value` (строка; для минут отдыха родитель при необходимости приводит тип при изменении, как уже делает `Number(event.target.value)`).
- Список опций: массив вида `{ value: string; label: string }[]` (для упражнений — из `id`/`name`, для отдыха — из чисел, преобразованных в строки для `value`).
- Опционально: `disabled`; при необходимости расширения — `className` на корневой обёртке (основной вид задаётся классами из `Select.css`).

Логику `useWorkoutSession`, `exerciseRegistry` и константу `REST_DURATION_OPTIONS` оставить в `App.tsx` (или рядом с местом использования), чтобы компонент оставался презентационным.

## 5. Стили

- В `App.css` сейчас для блока `.controls` заданы общие правила для `label` и `select` (высота, рамка, chevron, `disabled` и т.д.) — селекторы `.controls label`, `.controls select`, `.controls select:disabled`.
- Перенести в `Select.css` всё, что относится **именно к полю `Select`** (подпись + нативный список). На разметке `Select` использовать явные классы (например, BEM-подобные `select__label`, `select__field`), чтобы не зависеть от вложенности в `.controls`, либо оставить минимальную связку вида `.controls .select__field`, если так проще сохранить внешний вид без дублирования.
- В `App.css` оставить раскладку `.controls` (flex, gap, выравнивание) и стили **кнопок**; убрать дублирование правил для select/label, перенесённых в компонент.

Внешний вид списков и подписей после переноса должен совпадать с текущим.

## 6. Этапы реализации

1. Добавить папку `Select`, `Select.css`, импорт стилей в `Select.tsx`, баррель `src/components/index.ts`.
2. Заменить в `App.tsx` оба блока label+select на использование `<Select />` с разными пропсами.
3. Синхронизировать `App.css` и `Select.css` по п. «Стили» выше.

## 7. Проверка отсутствия регрессии

- Ручная проверка: оба списка открываются, значения меняются, выбор упражнения блокируется при `isRunning`, отдых меняется как раньше.
- `npm test` / `npm run build` (или актуальные скрипты проекта) проходят без ошибок.

## 8. Критерии готовности

- В `App.tsx` нет дублирования разметки двух select; используется один импортируемый `Select` из `src/components`.
- Стили внешнего вида `Select` живут в `src/components/Select/Select.css`, а не размазаны только по `App.css`.
- Публичные импорты между папками `src` идут через `index.ts` с явными экспортами.
- Наблюдаемое поведение UI и связи с хуками совпадают с состоянием до рефакторинга.
