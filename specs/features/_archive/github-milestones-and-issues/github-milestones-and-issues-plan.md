# План: GitHub Milestone, Issues и связь со спеками

Связанный чеклист: [github-milestones-and-issues-implementation-tasks.md](./github-milestones-and-issues-implementation-tasks.md).

## 1. Контекст

Команда ведёт планы в репозитории (`specs/features/`, `specs/fixes/`, `specs/refactor/`). Отдельно на GitHub удобно иметь **Milestone** как контейнер эпика, **Issues** как декомпозицию работ и при желании **Wiki** для развёрнутого ТЗ. Сейчас это не зафиксировано в репозитории: нет единого описания процесса, шаблонов Issues и указаний для агента.

## 2. Цель

- Документировать рекомендуемую схему: Milestone → Issues → ссылки на `specs/…` и Wiki.
- Добавить шаблоны Issues в `.github/ISSUE_TEMPLATE/` для фичи, исправления, рефакторинга и «эпика плана».
- Добавить правило Cursor, чтобы при запросе трекинга на GitHub агент выдавал структуру Milestone, список Issues, черновик Wiki и примеры команд `gh`.
- Кратко связать корневой `README.md`, `AGENTS.md` и `specs/README.md` с новой документацией.

## 3. Границы

Входит:

- Файл `docs/github-planning.md` с инструкциями и примерами `gh` / API.
- Шаблоны Issues и `config.yml` для выбора шаблона.
- Правило `.cursor/rules/github-planning-artifacts.mdc`.
- Точечные ссылки из существующих документов.

Не входит:

- Автоматический CI, создающий Milestone/Issues без участия человека.
- Обязательное использование Wiki (опционально по репозиторию).
- Изменение продуктового кода приложения.

## 4. Критерии готовности

- Документ `docs/github-planning.md` читается как пошаговая инструкция с примерами.
- В GitHub при создании Issue доступны шаблоны (после push ветки).
- В `AGENTS.md` и правилах есть отсылка к процессу GitHub-артефактов.

## 5. Риски

- Лейблы в шаблонах могут отсутствовать в репозитории GitHub — в шаблонах либо не указывать `labels`, либо использовать существующие.  
  Мера: не задавать обязательные несуществующие лейблы в front matter.
