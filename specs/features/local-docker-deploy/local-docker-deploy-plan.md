# План: локальное развёртывание в Docker

Связанный чеклист: [local-docker-deploy-implementation-tasks.md](./local-docker-deploy-implementation-tasks.md).

## 1. Контекст

- Проект — SPA на **Vite + React** (`npm run dev` / `npm run build` / `npm run preview`).
- В репозитории **нет** `Dockerfile`, `docker-compose` и инструкций по контейнеризации.
- Приложение использует **веб-камеру и микрофон** (MediaPipe, Web Speech API). Для `getUserMedia` в браузере нужен контекст **HTTPS** или **localhost** — при доступе с хоста как `http://localhost:<порт>` (проброс порта из контейнера) условие «localhost» выполняется.

## 2. Цель

Иметь **воспроизводимый** способ собрать статическую выкладку приложения и открыть её **локально** через Docker, без ручной установки Node на машине, на которой только Docker (опционально — отдельный сценарий для разработки с hot reload).

## 3. Границы

**Входит:**

- Описание целевой схемы: **multi-stage** образ (этап сборки на Node, этап выдачи статики через **nginx** или эквивалент с `try_files` для SPA).
- Файлы в корне репозитория: `Dockerfile`, при необходимости `docker-compose.yml` (или `compose.yaml`), `.dockerignore`.
- Настройка прослушивания на `0.0.0.0` и проброс порта (например `8080:80`).
- Краткая документация в **README** (раздел «Docker»): команды `docker build`, `docker run` / `docker compose up`, ожидаемый URL, отсылка к требованиям браузера.
- Проверка: после `npm run build` внутри образа отдаётся `dist/`, маршруты React Router открываются при обновлении страницы (fallback на `index.html`).

**Не входит (явно):**

- Продакшен-хостинг, TLS внутри контейнера, CI-публикация образа в registry.
- Изменение бизнес-логики приложения.
- Обязательный dev-контейнер с монтированием исходников (можно оставить вторым этапом по желанию команды).

## 4. Технические принципы

1. **Сборка:** в builder-стадии — установка зависимостей по политике репозитория (exact-версии, при сборке в Docker — `npm ci` при наличии закоммиченного `package-lock.json`).
2. **Выдача статики:** nginx (лёгкий образ, привычный `try_files $uri $uri/ /index.html`).
3. **Базовый путь:** приложение собирается с `base: '/'` (текущая конфигурация Vite); при смене `base` в будущем — синхронно обновить конфиг сервера.
4. **Кэш слоёв:** копировать `package.json` + lock-файл до копирования остального исходника, чтобы кэшировать `npm ci`.
5. **Размер и безопасность:** финальный образ без исходников и без devDependencies; не класть секреты в образ.

## 5. Команды (черновик для реализации)

После появления файлов в репозитории ожидаемый локальный сценарий:

```bash
docker build -t workout-counter-react:local .
docker run --rm -p 8080:80 workout-counter-react:local
```

Либо с Compose:

```bash
docker compose up --build
```

Открыть в браузере: `http://localhost:8080` (порт уточнить в итоговом `compose` / README).

## 6. Ручная проверка готовности

- Сборка образа завершается без ошибок.
- Главная страница открывается, статика грузится.
- Переход по внутренним маршрутам и **прямой заход по URL** (например обновление страницы на вложенном маршруте) не даёт 404 от nginx.
- Камера/микрофон проверяются вручную в Chrome/Edge на `localhost` (ограничения браузера те же, что и без Docker).

## 7. Риски и замечания

- **Safari / строгие политики:** поведение медиа-API зависит от браузера; Docker это не меняет.
- **Доступ по IP машины в LAN** (`http://192.168.x.x:8080`) может **не** считаться secure context для камеры — для проверки медиа предпочтительно именно `localhost`.
