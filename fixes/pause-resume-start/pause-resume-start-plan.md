# План исправления: старт после паузы возобновляет сессию

Ссылка на общие правила: [README.md](../../README.md), [fixes/README.md](../README.md).

## Контекст

Сейчас кнопка и голосовая команда `Старт` после `Пауза` фактически перезапускают упражнение: сбрасываются runtime-состояние и внутреннее состояние детектора. Это ломает ожидаемый сценарий тренировки, где пауза должна лишь временно остановить обработку.

## Цель

Сделать поведение сессии предсказуемым:

- `Пауза` останавливает выполнение текущего упражнения без сброса прогресса.
- `Старт` после паузы возобновляет ту же сессию с текущими счётчиком и фазой.
- Перезапуск с нуля остаётся доступным через `Сброс`.

## Этапы

1. Разделить в `start()` сценарии "новый запуск" и "возобновление после паузы".
2. Убедиться, что при возобновлении не происходит пересоздание состояния детектора и runtime.
3. Обновить документацию по управлению сессией, чтобы поведение `Старт`/`Пауза` было однозначным.
4. Прогнать линтер по изменённым файлам.

## Критерии готовности

- После `Пауза` -> `Старт` счётчик повторений и фаза продолжаются с прежнего места.
- Сессия по-прежнему стартует "с нуля", если до этого не было паузы.
- Описание в `README.md` и/или `docs/voice-commands.md` не противоречит новому поведению.
- Нет новых lint-ошибок в изменённых файлах.
