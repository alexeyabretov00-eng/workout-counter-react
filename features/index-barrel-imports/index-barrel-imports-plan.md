# План: импорты через index.ts

## 1. Контекст

В проекте часть импортов ссылается на конкретные файлы (например, `../exercises/registry`), из-за чего API модулей распределён по множеству точек входа. Это усложняет навигацию и делает рефакторинг путей более шумным.

## 2. Цель

Сделать единый подход: межмодульные импорты выполнять через папки, где публичные сущности реэкспортируются из `index.ts` через явные именованные экспорты.

## 3. Подход

- Добавить `index.ts` в основные модульные каталоги `src/hooks`, `src/exercises`, `src/services` и при необходимости другие модули `src/*` с явными именованными реэкспортами (без `export *`). Каталог `src/render` удалён; отрисовка сосредоточена в `src/utils` (`pose.ts`, `canvas.ts`).
- Обновить существующие импорты в `src` на импорт из папок (без обращения к конкретным файлам), где это безопасно и не создаёт циклических зависимостей.
- Зафиксировать правило в документации для разработчиков.
- Зафиксировать отдельное правило в `.cursor/rules` для ИИ-агентов.

## 4. Критерии готовности

- В модульных каталогах есть `index.ts` с актуальными реэкспортами.
- Импорты между модулями в `src` используют папочные точки входа.
- В документации проекта есть явное правило про импорт через `index.ts`.
- В `.cursor/rules` добавлено правило для ИИ о папочных импортах через `index.ts`.
